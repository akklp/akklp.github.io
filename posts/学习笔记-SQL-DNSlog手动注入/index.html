学习笔记-SQL-DNSlog注入

0x014 DNSlog注入学习笔记

1. 原理

  • 分类：DNSlog注入属于盲注的一种。
  • 优势：相比于基于布尔或时间的盲注，DNSlog注入的效率更高。因为传统盲注需要逐个字符进行猜测（测试次数多），而DNSlog可以直接将一串结果回显在DNS日志中。
  • 使用场景：
  • 当网站存在WAF绕过困难，手工注入或使用工具（如SQLMap，可能被封IP）效率极低时。
  • 页面没有直接回显，属于盲注场景。

2. 注入前提条件

想要成功利用DNSlog注入，必须满足以下权限要求：

  • MySQL具有读写文件的权限：MySQL服务器中的 secure_file_priv 配置不能被限制为禁止读写（需要允许对当前目录或无限制读写）。如果不满足此条件，将无法使用 load_file() 函数。

3. 核心概念剖析

3.1 load_file() 函数

这是一个MySQL的内置函数，主要用于读取文件内容。

  • 不仅可以读取本地机上的文件（如：select load_file('c:\\benben.txt');）。
  • 还可以读取网络上共享的文件。

3.2 UNC 路径

  • 全称：Universal Naming Convention（通用命名规则）。

  • 作用：常用于Windows系统中局域网共享文件或打印机的标准命名格式。

  • 格式：\\servername\sharename\directory\filename

  • 例如：\\192.168.1.123\123\benben.txt

  • 应用机制：UNC路径中不仅可以填写IP地址，还可以填写域名。当系统尝试访问该UNC路径时，如果填写的是域名，系统会首先发起DNS解析请求，这是DNSlog注入的利用核心。

3.3 DNSlog 工作原理

  1. 攻击者在DNSlog平台获取一个专属的临时域名（例如 rywtat.dnslog.cn）。
  2. 在SQL注入点利用 concat() 函数将想要查询的SQL语句结果（如 database()）与专属域名拼接在一起，作为子域名。
  3. 利用 load_file() 函数去请求构造好的UNC路径（例如：\\security.rywtat.dnslog.cn\abc）。
  4. MySQL在尝试加载此路径时，会向网络发起DNS查询。
  5. 攻击者在DNSlog平台刷新记录，即可在查询日志中看到被带出的数据（如查看到的请求是 security.rywtat.dnslog.cn，即可知道数据库名为 security）。

4. 常用DNSlog平台

  • http://ceye.io （个人使用，需注册，可用于配合工具如SQLMap的API注入）
  • http://www.dnslog.cn/ （临时获取域名，简单快捷，视频中主要演示平台）
