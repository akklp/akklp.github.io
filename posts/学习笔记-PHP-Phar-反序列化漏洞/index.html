Phar 反序列化漏洞

Phar 漏洞原理介绍

1. 什么是 Phar 文件？

Phar（PHP Archive）是 PHP 里类似于 Java 中 JAR 的一种打包文件。它可以将多个 PHP 文件及其他资源打包成一个可执行的文件。对于 PHP 5.3 及以上版本，默认支持 Phar 扩展。 使用 phar:// 伪协议可以读取和解析此类打包文件。

2. Phar 文件结构

一个标准的 Phar 文件由以下四个部分组成：

  1. Stub（存根）：
  • 文件的标识符。格式必须包含 __HALT_COMPILER(); ?>。
  • 示例：xxx<?php xxx; __HALT_COMPILER(); ?>。PHP 解析器只要发现这段代码，就会将其识别为 Phar 文件，而不关心文件的实际后缀名。
  1. Manifest（清单/属性信息）：
  • 存放被压缩文件的属性等信息。
  • 核心漏洞点：这里面包含了一个 Meta-data（元数据）字段，该字段的内容是以序列化的字符串形式存储的。
  1. Contents（文件内容）：
  • 实际被压缩文件的内容。
  • 数据占用空间。
  1. Signature（签名）：
  • 放在文件末尾，用于验证文件的完整性。

3. 漏洞触发机制

当 PHP 使用受影响的文件操作函数（如 file_exists(), md5_file(), file_get_contents() 等）配合 phar:// 伪协议去读取一个 Phar 文件时，PHP 会自动解析该文件。 在解析过程中，PHP 会自动将 Manifest 中的 Meta-data 字段的序列化数据进行反序列化。如果攻击者能够控制这个 Meta-data 里的内容，并且目标代码中存在可利用的魔术方法（如 __destruct, __wakeup），就能触发反序列化漏洞。

4. 漏洞利用的四个必要条件

  1. 上传入口：目标服务器上必须允许上传文件（即使只允许上传图片，因为 Phar 不看后缀，可以将 .phar 改为 .jpg 或 .png 上传）。
  2. 存在反序列化跳板：目标代码中必须有可利用的类，且包含魔术方法作为 POP 链的触发点。
  3. 存在文件操作函数：目标代码中存在受影响的文件操作函数，并且其参数是用户可控的。
  4. phar:// 协议未被过滤：目标环境支持并允许使用该伪协议。(注：生成 Phar 文件需要配置 php.ini 中的 phar.readonly = Off，但触发漏洞不需要此配置)。
