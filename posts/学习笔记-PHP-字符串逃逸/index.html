学习笔记-PHP-字符串逃逸

一、 基础原理与核心概念

1. 什么是字符串逃逸？

在 PHP 中，一般数据经历 serialize()（序列化）后，在进行 unserialize()（反序列化）之前，如果经过了某些过滤函数（如 str_replace 关键字替换），导致序列化字符串的长度发生了变多或变少，就会引起长度标识与实际内容不匹配，从而导致反序列化过程被破坏或被恶意利用。这种漏洞被称为反序列化属性逃逸（字符串逃逸）。

2. 反序列化的两个重要特性（逃逸的前提）

特性一：严格按长度读取 序列化引擎在解析字符串时，是严格按照前面指定的长度标识来读取的。例如 s:4:"abcd";，引擎看到 s:4，就一定会往后读取 4 个字符作为字符串的内容。

特性二：合法闭合即停止 当反序列化引擎读取到满足当前对象成员属性数量的合法闭合符（如 }）时，就会认为反序列化结束。在合法闭合符之后的任何字符串，都不会影响反序列化的正常执行。

二、 场景一：字符减少（吃掉有效代码）

1. 原理剖析

当过滤函数将长字符串替换为短字符串时（例如：flag (4字符) 替换为 hk (2字符)，每次替换减少 2 个字符），原本设定的长度就会大于实际字符串的长度。

为了满足设定的长度，反序列化引擎会向后继续读取（吞噬），这会导致原本属于序列化语法结构的代码（如 ";s:4:"pass";s:8:"）被当作字符串内容读取进去。

2. 攻击思路与步骤

思路： 利用第一个可控变量“吞噬”掉中间的语法结构结构，将我们精心构造的恶意代码放在第二个可控变量中，使其暴露出来成为独立的语法结构。

步骤：

  1. 确定恶意 Payload： 构造出能够满足攻击目标的序列化字符串（如修改某个属性的值）。
  2. 计算被吞掉的结构长度： 计算从第一个可控变量的结尾，到我们注入恶意 Payload 的起点之间，有多少个语法结构字符需要被“吃掉”。
  3. 计算替换次数： 替换次数 = 需要吃掉的字符总数 ÷ 每次替换减少的字符数。
  4. 构造最终输入： 在第一个变量中输入所需数量的替换词，在第二个变量中闭合代码并输入 Payload。

三、 场景二：字符增多（吐出有效代码）

1. 原理剖析

当过滤函数将短字符串替换为长字符串时（例如：ls (2字符) 替换为 pwd (3字符)，每次替换增加 1 个字符），原本设定的长度就会小于实际字符串的长度。

因为引擎严格按照原先指定的长度读取，读取完毕后，多出来的字符就会被“挤出（吐出）”原有字符串的范围。如果多出来的这部分字符刚好符合 PHP 反序列化的语法结构，它就会被作为新的成员属性被解析。

2. 思路与步骤

思路： 在同一个可控变量中，前面填充需要被替换的关键词，后面紧跟我们构造的恶意 Payload。通过替换增加的长度，把我们的恶意 Payload 刚好“挤”到合法字符串之外，成为独立的语法结构。

步骤：

  1. 构造 Payload： 写出你想添加或修改的属性的完整序列化形式，并在末尾加上闭合符（如 }）。
  2. 计算 Payload 长度： 统计构造好的这段 Payload 有多少个字符。
  3. 计算替换次数： 替换次数 = Payload字符长度 ÷ 每次替换增加的字符数。
  4. 构造最终输入： 输入 = (替换词 × 替换次数) + Payload。

四、 总结与排错技巧

  1. 确定方向： 拿到题目后，首先观察 str_replace（或其他过滤函数）是变长还是变短。
    • 变短（减少）： 利用第一个变量吞噬中间结构，在第二个变量写 Payload。
    • 变长（增多）： 利用不断增加的长度，在同一个变量末尾将 Payload 挤出。
  2. 计算： 字符串的长度计算必须分毫不差。特别是在“字符减少”的场景中，如果计算有误，会导致引擎无法正确识别后续的反序列化语法格式（如误将 s: 的一部分截断），从而导致 unserialize() 返回 false。
  3. 废弃后续代码： 无论是增多还是减少，通常都需要在我们伪造的 Payload 末尾加上 }，以便提前结束对象的反序列化过程，防止原有代码（被破坏后的残余代码）导致解析报错。
