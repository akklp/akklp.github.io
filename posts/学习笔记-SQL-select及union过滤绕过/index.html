SQL注入：select及union过滤绕过方式笔记(以Less-27为例)

1. 前置测试与环境分析

在进行关键字绕过前，需要先判断当前环境的基础闭合方式和被过滤的字符。

  • 闭合方式测试：通过输入单引号 ?id=1' 发现报错，判断为单引号闭合。
  • 注释符被过滤：尝试使用 # 或 --+ 发现页面依然报错或无法正常闭合，说明注释符已被过滤或替换。由于注释符被吃掉，只能使用闭合后半段的方式（例如 or '1'='1）来保证 SQL 语句的语法正确。
  • 空格被过滤：测试发现空格也无法使用，会被直接过滤。
  • 空格绕过方案：在 URL 中使用 %0a（换行符的 URL 编码）来替代空格。

2. union 和 select 绕过核心方法

当系统检测到敏感单词（如 union 或 select）并将其删除或拦截时，可以尝试以下几种绕过方式：

方法一：大小写绕过

原理：某些简单的 WAF 或过滤规则只针对全小写（或全大写）的关键字进行匹配。如果在过滤时没有统一转换为小写再进行检查，就可以通过改变字母大小写来绕过。 操作示例：

  • 将 union 修改为 uNion。
  • 将 select 修改为 seLect。

方法二：双写/复写单词绕过

原理：如果后台代码仅仅是简单地将敏感单词替换为空字符串，并且只执行一次（没有使用循环剔除），可以通过在关键字中间嵌套一个关键字来绕过。 操作示例：

  • 当后台把 union 替换为空时，输入 uniunionon。
  • 执行过滤后，中间红色的 union 被删除，剩下的部分 uni 和 on 恰好拼接成了完整的 union 关键字。
  • 此方法适用于仅单次剔除敏感词的小型站点或简单代码逻辑中。

方法三：尝试报错注入

原理：如果目标站点对 union 和 select 过滤得非常严格，大小写和双写都无法绕过，且页面有数据库错误信息回显，可以放弃使用联合查询，转而使用报错注入。 操作示例：

  • 利用 updatexml() 或 extractvalue() 等函数，构造错误的 XPath 格式，让数据库在报错信息中带出我们需要的数据。

方法四：其他绕过思路补充

  • 内联注释绕过：在关键字中间插入 //（例如 uni//on），但前提是目标环境没有过滤掉注释符。
  • URL 编码绕过：除了使用 %0a 代替空格，有时也可以尝试其他不可见字符的 URL 编码（如 %a0），但这极度依赖于具体的应用环境和中间件解析特性，实验中可能会有出入。 less-28 有一种过滤是过滤相连的union select，使用union%A0可以绕过
